# 封面与截图制作质量

## 先确定素材来源

从已有成品、品牌文件、真实截图、授权照片和录屏选择本轮需要的输入。真实 UI、原始图标与准确文字可以直接合成，不要求图片模型或 API；需要新位图时才使用可用的图片生成能力。工具不可用不应阻止其他素材的制作，也不能把几何占位图标成已完成的生成图。

## 封面：用具体主体解释产品

- 选择能说明产品用途的主体、场景或真实成果，先回答用户能做什么。抽象文件夹、光圈或渐变可以辅助构图，但不能取代产品表达。
- 确定一个主要标题和一条必要的说明，品牌标识为辅助。避免重复图标、功能堆砌和空泛口号；外部设备形象不暗示品牌背书或未经验证的兼容性。
- 为主体、标题及可能的视频播放遮罩分别安排空间；检查缩略效果、文字边界和裁切。底图不足时调整布局，不强行拉伸主体。
- 根据目标项目的视觉与受众选择颜色、字体和质感，不固定为深色、蓝色、玻璃或某个字体。照片、插画、真实 UI 与文字的角色应明确。

## 截图：让用户看到如何完成任务

- 每张图写清用户目标、真实页面、操作与可见结果，再决定标题。用有内容的演示状态展示产品，避免只宣传空列表、设置项或入口。
- 根据界面内容逐张选择展示比例、裁剪及位置。允许放大列表、展示完整预览或使用不同深浅背景，但保留系列的字体、间距和强调色联系。
- 真实截图保留像素内容和比例，不补画按钮、结果或文字。裁剪不能隐藏关键限制、付费状态和影响理解的上下文。不同语言使用真实对应语言截图。
- 简短标题说明收益，辅助文字补充任务或限制。不要让重复的品牌行和装饰占据主体空间，也不机械固定 UI 占比或截图数量。
- CONCEPT 仅用于明确的概念交付，不能用抽象插画替代用户要求的正式 UI 截图。缺少截图时记录缺口；在允许设备操作的任务中按测试流程获取真实截图。

## 合成与溯源

优先用确定性合成保留真实截图、授权照片、原始图标和文字。代码绘制背景、排版、边框和说明是有效制作方法；问题是用通用几何占位内容替代产品证明，而不是使用代码本身。

在输出目录保存 `source-map.json`，逐张记录 Asset ID、源文件相对路径、SHA-256、来源类型（真实截图/授权素材/生成底图）、裁剪框、等比缩放、放置位置、最终文案及输出路径。使用多种来源时逐项记录，不推断历史底图的模型或授权。

## 样稿与系列验收

先完成封面和一张代表截图，检查产品辨识度、文字层级、UI 清晰度、声明准确性及缩略可读性，修正后扩展全组。无需将可逆迭代自动变成用户审批门禁。

输出一张整套联系表，检查重复画面、样式突变、主体大小、标题节奏和功能覆盖。逐张检查最终位图；记录已通过与未验证项。尺寸检查、Prompt 一致性或脚本成功不能替代视觉验收。

现有有效作品可作为方法参考，不复制其他产品的品牌、照片、文案或功能声明。发布和后台上传仍需遵循用户授权范围。
