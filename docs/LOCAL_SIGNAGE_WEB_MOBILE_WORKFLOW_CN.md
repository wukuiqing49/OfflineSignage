# Local Signage 手机 Web 操作流程与优化方向

> 更新日期：2026-08-14
> 范围：局域网手机浏览器控制，不包含支付、账号、云端管理和公网穿透。

## 1. 产品结论

手机 Web 的核心不是把全部后台功能缩到小屏幕，而是让现场人员在一分钟内完成四件事：连接屏幕、确认当前状态、添加或选择内容、开始播放。设备管理、诊断和高级 Scene 编辑属于低频工作，必须从主控制路径中分离。

当前操作台按三个主入口组织，高级设置从“当前设备”进入：

| 工作区 | 主要任务 | 使用频率 |
|---|---|---|
| 当前设备 | 查看当前设备、语言和连接状态；进入高级设置或多设备管理 | 中低频 |
| 发送内容 | 发送图片、视频、文字、直播和网页/HTML，管理已保存内容 | 高频 |
| 播放控制 | 查看当前播放状态，暂停/继续、静音和音量控制 | 高频 |

高级设置包含 fallback、全屏/常亮/恢复设置、配对码、诊断和错误记录，不占用主导航入口。

## 2. 标准手机操作流程

### 2.1 首次连接

```text
广告屏无内容页显示二维码
-> 手机与广告屏进入同一局域网
-> 扫码打开一次性 pairingToken URL
-> 微信内置页提示使用系统浏览器，不消费 pairingToken
-> Server 消费 Token 并签发 8 小时 Web Token
-> 浏览器立即清理地址栏中的 pairingToken
-> 自动申请 Control Session
-> 进入“发送内容”页
```

验收重点：二维码不可重复消费；微信转交系统浏览器前不消费 Token；地址栏不保留 Token；若二维码已被其他页面消费则先验证当前浏览器保存的旧 Web Token，旧 Token 也失效后才提示重新扫码；页面和 Token 响应禁止缓存。

电脑首次连接不要求扫描二维码：在电脑浏览器打开广告屏显示的控制地址，输入广告屏上的 6 位数字一次性电脑配对码。电脑码与二维码使用相互独立的 5 分钟临时凭据，各自成功后立即失效，因此手机与电脑可以分别完成连接并获得独立 Web Token。电脑码连续输入错误会触发短暂锁定。

### 2.2 日常控制

```text
打开已配对标签页
-> 读取设备状态和最近资源
-> WebSocket 接收实时播放状态
-> 暂停/继续、上一项/下一项、停止或调节音量
-> commandId + revision 保证重试不重复执行
```

Android 播放屏仍只显示暂停/继续和状态；完整控制留在手机 Web。

### 2.3 添加内容

Content 工作区统一覆盖：

- 手机相册/文件中的图片和视频，显示上传进度，上传成功后自动播放。
- HTTPS 图片/视频链接由设备下载并缓存，断网后可继续播放；批量下载失败时回滚本批新增内容。
- HTTPS Web、Local HTML、HLS、DASH、RTSP 和纯文本资源。
- Resource 创建后自动生成基础 Scene，并加入默认 Playlist；需要显示参数时再创建自定义 Scene。

失败必须显示后端返回的可读错误，不允许静默失败。删除 Resource、Scene、Playlist、设备和错误记录前必须二次确认。

### 2.4 Scene 与 Playlist

```text
选择 Resource
-> 设置 FIT/FILL/CROP/STRETCH、背景、音量和静音
-> 创建 Scene
-> 选择一个或多个 Scene
-> 创建并播放 Playlist
```

Overlay 在独立子页追加到已有 Scene，支持静态文字和 Ticker；移除 Overlay 后立即刷新 Scene 数据。

### 2.5 多设备

```text
NSD/UDP 发现设备
-> 选择发现结果并输入目标设备 Token
-> Server 校验 deviceId、IP、端口与发现结果一致
-> 配对并持久化加密凭据
-> 勾选目标设备
-> 同步 Resource 或 Playlist
-> 统一播放、暂停、停止、静音或音量
```

设备离线只影响该设备结果，不应阻塞其他设备。Fleet 状态必须区分在线、离线、超时和远端错误。

### 2.6 多浏览器控制权

- 多个浏览器可以读取状态，同一时刻只有一个 Control Session 可以写入。
- 第二个浏览器显示当前匿名 Owner 和过期时间，并保持当前设备、发送内容和播放控制导航可用。
- 点击 Take control 后旧 Session 立即失效，新浏览器获得控制权。
- 页面离开时使用 keepalive 请求释放 Session；异常关闭时由 60 秒超时兜底。
- Session 状态接口不得返回其他浏览器的 `sessionId`。

## 3. 本轮已实现优化

- 控制台从 Ktor Kotlin 长字符串拆到 `feature_app/src/main/res/raw/web_console.html`。
- 移动优先布局，最小支持 280 px；手机采用“当前设备、发送内容、播放控制”三个底部主入口，680 px 以上使用双栏内容管理。
- WebSocket 负责播放状态；资源、Scene、Playlist 和设备按工作区刷新，避免轮询覆盖用户输入。
- 页面进入后台时关闭 WebSocket/停止工作区刷新，回到前台后恢复。
- 上传进度、操作 Toast、错误提示、删除确认、空状态、只读和 Take control 状态。
- Resource、Scene、Playlist、Overlay、Fleet、设置、配对码、诊断和错误管理入口统一。
- 动态业务内容使用 DOM `textContent`，不使用业务数据拼接 `innerHTML`。
- 页面响应增加 `no-store`、CSP、`no-referrer`、`nosniff` 和禁止 iframe 嵌入。
- 修复 Control Session 信息泄露：只读浏览器无法读取其他 Owner 的 Session ID。
- 控制台按浏览器语言默认显示简体中文或英文，系统页可即时切换，静态文案、动态列表、Toast、空状态和常见 API 错误统一走翻译字典。
- 首屏收敛为当前播放、暂停/继续、上一项/下一项、停止、静音、音量和快速播放；内容、设备与诊断继续放在独立工作区。
- Server、WebSocket 和 Control Session 分开显示健康状态，HTTP 可达但实时通道重连时不再误报整台设备离线。
- 初始化顺序调整为状态验证、实时通道、控制权、内容加载；Web Token 有效期为 8 小时，未过期 Token 可跨 Android 进程或设备重启继续使用，并在浏览器重新打开时恢复授权。
- Web 控制台同时保存 Token 到期时间，仅在剩余有效期不足 1 小时时续期，避免每 5 分钟生成新 Token；服务端对历史 Token 去重，并有界保留最多 32 个，支持多个已授权浏览器平稳轮换。
- 微信内置浏览器优先恢复当前浏览器已有的有效 Web Token；首次扫码仍只显示系统浏览器接管提示且不消费一次性 pairingToken。系统浏览器交换成功后再清理地址栏，交换失败时会验证当前浏览器原有 Web Token。
- 广告屏同时显示二维码和 6 位数字电脑配对码；两者使用独立的一次性凭据。未授权电脑打开控制地址后可直接输入数字码，已授权浏览器也可在“更多设置”查看当前码。
- WebSocket 同时广播播放状态与控制权变化；另一浏览器接管后，旧控制端立即校验 Session 并切换为只读。实时通道恢复期间使用低频 HTTP 状态刷新兜底。
- 过期配对二维码仍返回可读控制台并说明重新扫码；访问 Token 失效使用 401，控制 Session 失效使用 409 + CONTROL_SESSION_INVALID。
- 图片和视频使用独立选择入口：手机调用系统相册或文件选择器，电脑支持点击选择与拖放；两端统一执行类型校验、200 MB 大小校验、文件预览和上传进度。
- 对 Android 文件选择器或桌面拖放返回的空 MIME / application/octet-stream，Server 仅按受支持图片和视频扩展名补充 MIME，其他文件继续拒绝。

## 4. 后续功能方向

### P0：现场可靠性

1. Chrome Android、Samsung Internet、Safari iOS 真机兼容与弱网测试。
2. 上传中断后可恢复或明确重试；大文件剩余时间与服务端落盘状态可见。
3. 在已有 Server、WebSocket、Control Session 状态基础上，继续增加播放器、存储、网络和每台目标设备的独立健康状态。
4. 操作审计：本地记录时间、匿名客户端、设备、命令、结果和错误码，不记录 Token 或内容正文。
5. 批量命令显示每台设备结果，并支持只重试失败设备。

### P1：内容运营效率

1. Playlist 拖拽排序、每个 Scene 时长、禁用项和预览摘要。
2. Scene 编辑改为保存草稿、预览、发布三步，避免直接影响正在播放内容。
3. 常用内容模板：图片轮播、欢迎屏、菜单板、直播流、通知条。
4. 本地排期：日期、星期、时间段、优先级和过期自动下线。
5. 资源缩略图、筛选、搜索、使用中引用提示和安全批量清理。

### P2：企业部署

1. 控制台 CSS/JS 拆成独立静态资源，使用外部脚本和资源 Hash，移除 CSP 的 `unsafe-inline`。
2. 基于客户网络模型决定设备证书、局域网 TLS 或反向代理部署。
3. MDM/Kiosk、版本灰度、升级回滚、配置备份与恢复。
4. 本地匿名播放统计与设备健康趋势；默认不上传公网。
5. 权限角色、账号和云端管理仅在明确商业需求后设计，不作为 Local-first 默认依赖。
