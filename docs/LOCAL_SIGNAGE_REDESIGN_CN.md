# Local Signage 全页面重设计方案

## 范围与设计方向

覆盖 Android 展示端的启动、欢迎、连接与播放、帮助、文章、授权、法律与隐私，以及局域网控制台的播放、发送、内容、设备、记录与其编辑弹窗。以当前源码和历史模拟器截图为基线；本文是设计方案，不代表实现或视觉验收完成。

产品的核心体验是「看见屏幕状态，安全地改变屏幕内容」。展示端应远距离清楚地引导连接，在播放时让内容成为主角；控制台应让操作者始终知道当前目标、操作结果和下一步。借鉴 Apple HIG 的信息优先级、适配、可感知反馈和可访问性原则，组件、焦点及导航仍遵循 Android 和 Web 的平台习惯。

## 现状与设计问题

- 既有连接页将二维码、地址和配对码集中，并将帮助与授权移到次级区域；这条主路径值得保留。应进一步区分连接成功、等待连接、网络不可用和用户主动打开面板等状态，避免用颜色单独表达状态。
- 历史平板帮助页将八个入口平均摆成两组，每一行均带独立描边，重点不足、重复边框较多。可保留两个主题组和全部入口，改为更安静的分组列表，并让最常用的快速开始更容易发现。此判断基于历史截图，当前不同尺寸的实际画面仍需核对。
- 控制台固定展示目标、连接、授权、控制权、语言和帮助，信息都重要，但页面头部可能在窄屏竞争空间；需要让当前目标和控制权优先，其余功能仍可发现。
- 播放预览、播放指令和发送入口同时出现；设计应明确预览代表当前设备的状态，命令结果跟随被控制设备显示，避免将预览或请求完成误认为实际播放成功。
- 用户素材是展示端的视觉主体，不应让任何固定品牌、模糊或动效遮挡广告内容。

## 统一设计语言

- 表面分为页面背景、内容面板和叠加层三层。沿用现有亮暗主题与品牌蓝；蓝色用于主要操作及有文字说明的正向状态，错误、警告与禁用均有文字和图标，不只靠颜色。
- 字体使用系统字体；标题、正文、辅助说明分别保持稳定层级，正文优先自然换行。Android 使用 sp 与既有样式；Web 使用可缩放的相对字号。避免为适应放大字体而缩小文本。
- 常规触控目标至少 48dp，Web 触屏操作目标建议至少 44 CSS px；每个图标按钮提供可访问名称。焦点应在遥控器、键盘和触屏操作时清晰可见。
- 宽屏按可用宽度分栏，窄屏与大字体改为单栏，不隐藏功能。为滚动内容和系统栏分别分配边衬；播放画面保持全屏，连接和操作控件避开系统栏、刘海与遥控器焦点边缘。
- 减少重复描边：组容器负责分组，行间用留白或细分隔。保留组件可点击、禁用、焦点、加载和错误状态的明显差异。色值与对比度必须从实际主题资源计算后确定，不能仅凭截图估测。

## Android 展示端

### 启动与欢迎

启动页保持短暂、安静，启动失败时在当前页面说明问题并提供重试。欢迎页以「连接设备并开始播放」为主线：介绍、连接方式、开始操作清晰分层；宽屏左右排列，窄屏依次排列。已有完成状态和跳过逻辑保持一致。

### 连接与播放

连接面板优先显示屏幕名称与连接状态；主区域展示二维码及清晰的地址、配对码，附一句同一局域网提示。帮助、授权和联系入口保持可发现但次级。失败时明确网络状态与下一步；长地址可换行或提供可访问的完整文本。扫码框保持高对比度和足够尺寸。正常播放时仅在需要时显示控制或错误信息；恢复、返回、横竖屏及重建沿用已有契约。

### 帮助与文章

帮助页保留「发布内容」「管理屏幕」两组及所有现有入口。两组宽屏并排、窄屏纵向排列；组内采用清晰的可点击列表行，首行突出快速开始，减少层层描边。文章页保持可滚动、可返回，内容宽度适合阅读，链接及小屏字体放大可操作。

### 授权与购买

先展示当前授权状态和权益，再展示可购买方案与价格，最后展示恢复购买、兑换和帮助。不可用方案解释原因，保留刷新入口；加载、购买中、失败、已拥有和恢复结果在相关区域就地反馈。三档方案及真实价格来自现有计费数据，不虚构优惠或权益；窄屏纵排，宽屏并列，支持长文案与大字体。

### 法律与隐私

法律中心保留全部文件入口和使用统计设置。开关旁说明当前状态、用途和关闭方式；统计不可用时说明原因。法律正文使用可滚动阅读宽度、清晰标题与返回入口；不通过视觉改版更改已生效的统计行为或隐私承诺。

## 局域网控制台

### 共享框架

桌面侧栏保留「播放、发送、内容、设备、记录」五个入口和连接状态。顶部优先显示当前目标及控制权；帮助、语言、授权信息在空间不足时有明确且可访问的入口。移动端使用可滚动、可达的导航，切换页面不丢失未提交输入；保留现有链接与快捷入口。目标切换前后持续显示实际目标，失去控制权时解释只读原因及恢复入口。

### 播放

以当前屏幕预览和文字状态为第一层，播放/暂停、上一个、下一个为主要控制；停止、静音、音量与发送新内容为次级操作。在线、离线、加载、无内容和失败状态直接出现在预览或对应控制附近；状态刷新区分已发送请求与设备实际反馈。

### 发送

按现有内容类型提供明确选择，逐项呈现必要输入与目标。保持已有文件上传、远程资源、文本、网页等功能；校验贴近字段，上传或同步提供可见进度与可执行的失败恢复。发布前展示目标；多设备部分失败逐台列出结果，并保留只重试失败设备的既有流程。

### 内容

保留 Resource → Scene → Playlist 模型与现有三个分类。列表优先展示名称、类型、状态与常用操作；搜索和筛选靠近列表，空态提供相应创建入口。场景与列表编辑保留当前字段、顺序、取消和保存行为，复杂设置分组渐进展开，不隐藏已配置的高级内容。

### 设备

保留设备概况、列表、添加、分组及选择操作。设备行显示名称、连接及播放状态，并用文本说明异常；多设备操作明确选中数量与目标。设备离线和未授权应分别呈现，避免误以为命令已成功。

### 记录与诊断

记录保持时间、操作、操作端和结果，过滤器与刷新可见；清空操作与普通操作区分。窄屏按记录转换为可读的纵向条目，不能只裁切表格。诊断保留渐进展开、导出与错误清理；不可逆操作给出明确确认。

### 弹窗与反馈

每个弹窗只有一个明确任务和可见关闭方式；标题、字段、错误与操作顺序一致。保存前保留输入，失败后原位解释；长表单在小屏可滚动，按钮与键盘不互相遮挡。不得以装饰性动画代替进度或结果。

## 实施顺序与验收

1. 建立亮暗主题、文字、间距、焦点与状态的共享视觉规则；分别核对 Android 与 Web 的真实资源和对比度。
2. 实施展示端连接与欢迎、播放覆盖层，再处理帮助、文章、授权和法律页面；逐项核对现有入口、状态与返回路径。
3. 实施控制台共享框架，再依次处理播放、发送、内容、设备、记录及弹窗；保留既有 ID、接口和自动化契约。
4. 运行现有功能与 UI 门禁，检查 320/390px 手机、桌面宽屏、横竖屏、日夜模式、200% 字体、键盘、读屏与电视遥控器焦点。使用隔离测试数据；真实设备、购买和长时间播放分别记录。
5. 对比改动前后实际画面；静态源码、编译和示意不能替代运行与视觉验证。

参考：Apple HIG [Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)、[Loading](https://developer.apple.com/design/human-interface-guidelines/loading)。这些是跨平台设计原则，Android 和 Web 控件遵循各自平台约定。


## 2026-11-26 实际工程进度

已将共享视觉调整应用到 Android 实际资源：亮暗色板、按钮和分组列表、帮助/授权/法律页面的阅读间距、连接页和欢迎页使用的共享表面，以及播放授权提示的触控尺寸。控制台同步调整品牌色、导航、阅读层级、表面与按钮、焦点及减少动效策略，修复移动导航安全区高度与 padding 计量。此阶段保留全部 XML id、导航与 API 契约；不是全页面结构重写已完成的声明。

架构采用现有 app 壳 → feature_app → core 模块；共享视觉在已有 feature_app 资源维护。展示端不接管控制台的内容编辑职责；Resource → Scene → Playlist 和播放/Server 脱离 Activity 的约束继续有效。当前重点是呈现层，尚未新增 ViewModel 或改变存储和同步协议。

控制台发布流程 9 项 Node 测试通过；Playwright 使用隔离虚拟 API，部分失败后仅重试失败设备通过，中英文结果更新通过，1440/390/320px 无横向溢出，页面无 JavaScript 错误。证据在 doc/testing/evidence/redesign-20261126。Android UI 静态门禁通过（保留非 Tab ViewPager2 提示）。Android 实际安装、遥控器焦点、字体放大和日夜截图尚未复测，不把历史截图计为本次证据。

主色修正：按用户确认使用蓝色；浅色强调 #2563EB、深色强调 #91B8FF，绿色仅用于明确的成功状态。横竖屏按窗口可用尺寸及字体缩放适配，不通过锁定方向或缩小文字规避布局。

### 付费入口与页面层级复核

| 页面 | 首要信息与操作 |
| --- | --- |
| 启动与欢迎 | 品牌和开始设置，连接步骤按实际操作排序 |
| 连接与播放 | 网络、二维码和配对码优先。试用中和试用结束时以蓝色边框突出授权入口 |
| 帮助与文章 | 按任务分组，文章使用单栏阅读宽度和可缩放正文 |
| 授权 | 当前状态和可选套餐在前。价格加大，沿用年度推荐，权益说明和恢复入口跟随套餐 |
| 法律中心与正文 | 文件按列表排列，统计设置独立，正文保持阅读宽度 |
| 控制台播放与发布 | 当前目标与执行结果优先。免费版升级入口位于顶部授权状态旁 |
| 控制台内容、设备与记录 | 主视图优先显示当前任务，筛选、次要动作与结果靠近相关数据 |
| 控制台弹窗 | 现有 Pro 说明弹窗统一承担权益与购买指引，真实套餐与价格由 App 展示 |

依据 Apple Design Skill 的 Layout、Buttons、Accessibility 和 Feedback 原则组织视觉顺序、主操作、触控尺寸和状态反馈。Android Debug 构建并在 Pixel 8 启动成功。浏览器以模拟免费状态检查五个主页面和三种窗口尺寸，共 15 组，升级入口均可见，页面无横向溢出，升级弹窗可打开。真实购买、Android 大字体与遥控器尚未复验。

### 全页面细节复核

启动页移除重复说明并避免读屏重复朗读品牌。欢迎页标题和说明允许自然换行。配对页增加标题层级和连接状态朗读。帮助、法律中心和文档正文统一阅读行距。授权页的套餐标题可被读屏作为标题导航。控制台五个主页面统一标题分隔，发布目标增加蓝色标识，分组和记录数字便于对照。通用弹窗在低高度横屏中随正文滚动，操作可换行。

Android Debug 构建成功并安装到 Pixel 8，主页面启动成功。八种语言资源校验通过。浏览器以模拟免费版检查五个主页面在三种尺寸下的横向溢出和升级弹窗开关。大字体真机、遥控器和真实购买未复测。


## 用户参考图落地及边距约束（2026-11-26）

实际连接首页以用户提供的横屏图片为依据：左侧二维码、右侧连接信息、底部全宽蓝色权益栏及白色专业版入口。截图外黑底与窗口边框不属于产品UI。页面统一16dp内边距，页头和升级栏分别贴近上下安全边界；不可再次叠加居中卡片margin或把中部刘海安全区施加到不相交的页头/底栏。网络操作收进状态旁入口，热点失败留在本页解释；企业支持由帮助页进入。


## Pro入口最新约束（2026-11-26）

依据用户后续反馈，底部升级入口改为居中、最大420dp的紧凑卡片，不再铺满屏宽。使用金色皇冠矢量图、PRO品牌字样及真实授权状态，右侧白色按钮进入授权页；不恢复长营销标题。


## 2026-11-26 支付与辅助页面落地

支付首屏为皇冠PRO、真实授权状态、可见权益和等高三套餐；年度有推荐态，恢复/重试/说明/法律集中一行，窄屏或放大字体改纵向滚动，不隐藏入口。缺货弱化并禁用购买，不展示测试价格。帮助10入口双栏无嵌套卡片，法律中心文档/偏好双栏，文章720dp阅读宽度，欢迎页16dp边距与紧凑步骤。HTML沿用蓝色，桌面与竖屏导航保留，640–900px且低于500px的手机横屏使用96px侧栏、播放双栏；试用/免费升级用皇冠按钮，Pro不显示重复升级。证据为doc/testing/evidence/all-pages-20261126，设计预览不代替真实实现。当前真实支付目录不可用；真实购买、其他设备及本轮欢迎实机仍未验证。
