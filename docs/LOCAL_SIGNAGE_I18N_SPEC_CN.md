# Local Signage 国际化规范

## 主语言与回退

英文是产品、计费、帮助、法律和 Web 控制台文案的主语言。简体中文（`zh-CN`）是首个完整发布的译文。首批可选择的英文回退 locale 为 `ja-JP`、`ko-KR`、`es`、`de`、`fr`、`pt-BR` 与 `ru`。没有经过审核的语种统一回退英文。

没有完成产品文案和必需法律文件审核的语种，不得在语言选择器中作为可选语言展示。

## Android 应用

- 用户可见文案放在 `feature/feature_app/src/main/res/values/strings.xml`，并使用对应的 `values-*` 目录维护译文。
- 应用内法律文件放在 `raw/`；各语言使用 Android 资源限定目录，例如 `raw-zh-rCN/`。
- 帮助页面使用 string 资源，不能把帮助或法律文案硬编码进 Kotlin。
- 产品名、套餐名、试用状态、订阅条款和取消说明在每个已发布语言中必须含义一致。

## Web 控制台

- 控制台使用 BCP-47 locale 标识。当前已发布语言为 `en` 与 `zh-CN`。
- 默认语言取浏览器 locale；用户手动选择后保存到 `localStorage`。
- UI 文案必须经由 `tr(key)`，日期时间必须按已选 locale 格式化。接口返回的设备名、错误码等数据不由浏览器强行翻译。
- 新增语言时需补全 message pack 和 HTML 模板；缺失 key 必须安全回退英文。

## 法律与商店内容

- 隐私、条款、订阅和数据删除声明按已发布语言分别存放文件。
- 法律译文必须在发布前确认审核状态、生效日期和版本号。
- Google Play 商店文案、截图和订阅说明必须与应用内对应语言及商业承诺一致。

## 发布检查

1. 检查 Android strings 的 key、占位符和 raw 文件 UTF-8 编码。
2. 检查 Web message key 与语言选择器的 locale 值。
3. 检查长文案、字体缩放和各语言日期时间；发布 RTL 语言后再补 RTL 专项验收。
4. 验证每个已发布法律链接能打开对应语言文件或声明的英文回退。
